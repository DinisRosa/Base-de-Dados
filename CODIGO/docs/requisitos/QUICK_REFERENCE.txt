1️⃣  ENTIDADES PRINCIPAIS (8)
════════════════════════════════════════════════════════════════════════════════

LOCALIZACAO
  ├─ id_localizacao (INT, PK, AI)
  ├─ sala (VARCHAR 50)
  ├─ piso (VARCHAR 20)
  └─ edificio (VARCHAR 100)

DEPARTAMENTO
  ├─ id_departamento (INT, PK, AI)
  ├─ designacao (VARCHAR 100, NOT NULL)
  └─ descricao (VARCHAR 255)

RESPONSAVEL
  ├─ id_responsavel (INT, PK, AI)
  ├─ nome (VARCHAR 150, NOT NULL)
  ├─ data_nascimento (DATE, NOT NULL)
  ├─ id_departamento (INT, FK, NOT NULL)
  └─ aprova (BOOLEAN, DEFAULT TRUE)

EQUIPAMENTO ⭐ (Entidade Central)
  ├─ id_equipamento (INT, PK, AI)
  ├─ designacao (VARCHAR 150, NOT NULL)
  ├─ data_aquisicao (DATE, NOT NULL)
  ├─ fabricante (VARCHAR 100, NOT NULL)
  ├─ estado (VARCHAR 50, CHECK IN 5 valores) ⚠️
  ├─ estado_atual (VARCHAR 50, CHECK IN 5 valores) ⚠️
  ├─ descricao (VARCHAR 500)
  ├─ garantia (INT, DEFAULT 0, CHECK >= 0) 📅
  ├─ id_localizacao (INT, FK, NULLABLE)
  └─ id_departamento (INT, FK, NULLABLE)

TECNICO
  ├─ id_tecnico (INT, PK, AI)
  ├─ nome (VARCHAR 150, NOT NULL)
  ├─ especialidade (VARCHAR 100, NOT NULL)
  ├─ data_inicio_carreira (DATE, NOT NULL)
  └─ anos_experiencia (INT, CHECK >= 0)

MANUTENCAO
  ├─ id_manutencao (INT, PK, AI)
  ├─ tipo (VARCHAR 50, CHECK IN 4 tipos) ⚠️
  ├─ data_inicio (DATE, NOT NULL)
  ├─ data_fim (DATE, NULLABLE)
  ├─ descricao (VARCHAR 500)
  ├─ custo (DECIMAL 10,2, CHECK >= 0) 💰
  ├─ duracao (INT, CHECK >= 0) 📅
  ├─ horas_trabalho (DECIMAL 5,1, CHECK >= 0) ⏱️
  └─ id_equipamento (INT, FK, NOT NULL)

PECA
  ├─ id_peca (INT, PK, AI)
  ├─ designacao (VARCHAR 150, NOT NULL)
  ├─ preco (DECIMAL 10,2, CHECK >= 0) 💰
  ├─ custo (DECIMAL 10,2, CHECK >= 0) 💰
  └─ validade_peca (DATE)

ORDEM_SERVICO
  ├─ id_ordem (INT, PK, AI)
  ├─ descricao (VARCHAR 500, NOT NULL)
  ├─ estado_atual (VARCHAR 50, CHECK IN 4 estados) ⚠️
  ├─ data_criacao (DATE, DEFAULT CURDATE())
  └─ prioridade (VARCHAR 20, CHECK IN 4 prioridades) ⚠️

2️⃣  TABELAS DE MULTIVALORADOS (3)
════════════════════════════════════════════════════════════════════════════════

RESPONSAVEL_CONTACTO
  ├─ id_responsavel (INT, PK, FK)
  ├─ contacto (VARCHAR 100, PK)
  └─ ÚNICA: Sem limite de contactos por responsável

EQUIPAMENTO_CONTACTO_SUPORTE
  ├─ id_equipamento (INT, PK, FK)
  ├─ contacto_suporte (VARCHAR 100, PK)
  └─ ÚNICA: Sem limite de contactos por equipamento

TECNICO_CONTACTO
  ├─ id_tecnico (INT, PK, FK)
  ├─ contacto (VARCHAR 100, PK)
  └─ ÚNICA: Sem limite de contactos por técnico

════════════════════════════════════════════════════════════════════════════════
3️⃣  TABELAS DE RELACIONAMENTO N:M (3)
════════════════════════════════════════════════════════════════════════════════

MANUTENCAO_ORDEM (N:M)
  ├─ id_manutencao (INT, PK, FK)
  ├─ id_ordem (INT, PK, FK)
  └─ ➜ Uma manutenção gera N ordens; Uma ordem resulta de N manutenções

MANUTENCAO_PECA (N:M)
  ├─ id_manutencao (INT, PK, FK)
  ├─ id_peca (INT, PK, FK)
  ├─ quantidade (INT, NOT NULL, CHECK > 0)
  └─ ➜ Uma manutenção utiliza N peças; Uma peça é usada em N manutenções

INTERVENCAO_TECNICO (Entidade Relacional)
  ├─ id_intervencao (INT, PK, AI) ⭐
  ├─ id_manutencao (INT, FK)
  ├─ id_tecnico (INT, FK)
  ├─ cargo (VARCHAR 100)
  └─ horas_trabalho (DECIMAL 5,1)
  └─ ➜ Uma manutenção envolve N técnicos; Um técnico participa em N manutenções

ORDEM_SERVICO.prioridade (CHECK, 4 prioridades):

  ✓ MANUTENCAO → EQUIPAMENTO

  ✓ MANUTENCAO.horas_trabalho >= 0

  ✓ ORDEM_SERVICO.estado_atual IN (4 estados)

  ✓ PECA.preco >= 0
  ✓ PECA.custo >= 0
  ✓ MANUTENCAO_PECA.quantidade > 0
  ✓ TECNICO.anos_experiencia >= 0

6️⃣  OPERAÇÕES CRUD SUPORTADAS
════════════════════════════════════════════════════════════════════════════════

CREATE (Inserção):
  ✓ Departamentos com validação
  ✓ Equipamentos com estado e constraints
  ✓ Técnicos com experiência
  ✓ Manutenções com tipos
  ✓ Peças com preços
  ✓ Ordens de serviço com prioridades
  ✓ Contactos multivalorados (sem limite)
  ✓ Relacionamentos N:M

READ (Consulta):
  ✓ Equipamento com detalhes completos
  ✓ Manutenção com técnicos e peças
  ✓ Carga de trabalho por técnico
  ✓ Custos por departamento
  ✓ Histórico de auditoria
  ✓ Garantias vencidas
  ✓ Ordens por status

UPDATE (Atualização):
  ✓ Estado de equipamento (TRIGGERS auditoria)
  ✓ Localização do equipamento
  ✓ Dados de técnico
  ✓ Status de ordem de serviço
  ⚠️ Atualização dispara TRIGGERS automáticos

DELETE (Eliminação):
  ✓ Contactos multivalorados (CASCADE)
  ⚠️ Equipamento restringe se tem manutenções
  ⚠️ Peça restringe se tem manutenções

🔟 FLUXO TÍPICO: REGISTAR MANUTENÇÃO
════════════════════════════════════════════════════════════════════════════════

PASSO 1: Equipamento está em estado "Operacional"
PASSO 2: Criar registo em MANUTENCAO (tipo, data, custo, equipamento)
PASSO 3: Sistema atualiza EQUIPAMENTO.estado_atual = "Em Manutenção"
PASSO 4: TRIGGER registra alteração em AUDITORIA_EQUIPAMENTO
PASSO 5: Associar TECNICO via INTERVENCAO_TECNICO (cargo, horas)
PASSO 6: Registar PECA's utilizadas em MANUTENCAO_PECA (quantidade)
PASSO 7: Criar ORDEM_SERVICO (descrição, prioridade)
PASSO 8: Associar em MANUTENCAO_ORDEM (ligar ambas)
PASSO 9: Marcar MANUTENCAO como completa (data_fim)
PASSO 10: Atualizar EQUIPAMENTO.estado_atual = "Operacional"
PASSO 11: TRIGGER registra alteração em AUDITORIA_EQUIPAMENTO

⚠️  PONTOS IMPORTANTES
════════════════════════════════════════════════════════════════════════════════

1. AUDITORIA AUTOMÁTICA: Triggers registam automaticamente alterações
2. CASCATA DE DELETIONS: Contactos deletam com entidades (CASCADE)
3. RELACIONAMENTO DIRETO: EQUIPAMENTO-DEPARTAMENTO é 1:N (não N:M)
4. GARANTIA EM MESES: Campo inteiro = número de meses
5. CONTACTOS SEM LIMITE: Composite PK permite infinitos contactos
6. ESTADOS FIXOS: Apenas CHECK values, sem tabela separada
7. INTEGRIDADE FK: Cascata onde apropriado, RESTRICT noutros
